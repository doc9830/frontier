# FRONTIER

Процедурная космическая песочница: торговля, добыча, своя станция и флот.
Игра — это веб-приложение (React + TypeScript + Vite) и одновременно
Android-приложение: тот же билд упаковывается в APK, где игра работает внутри
WebView и сама обновляется из этого репозитория. Галактика генерируется на 128
систем: поле карты растёт вместе с их числом, поэтому расстояния между соседями,
цена прыжка топливом и время перелёта те же, что и в маленькой галактике.

## Что внутри

| Папка | Назначение |
| --- | --- |
| `src/` | игра: симуляция, панели интерфейса, сохранения в localStorage |
| `public/` | иконка, манифест PWA и офлайн-оболочка для браузера |
| `android/` | Android-оболочка: WebView, мост в игру и внутренний апдейтер |
| `scripts/` | сборка веб-бандла и публикация релизов |
| `version.json` | единственный источник версии: она попадает и в APK, и в веб-бандл |

## Игра в браузере

```bash
npm install
npm run dev        # разработка
npm run build      # dist/ — готовая игра
npm run verify     # типы, smoke-тесты, проверка рендера
```

## Игровой цикл

Интерфейс собран вокруг шести вкладок нижнего дока: `СИСТЕМА`, `ГРУЗ`, `КОРАБЛЬ`,
`ФЛОТ`, `ЛЕНТА`, `НАСТРОЙКИ`. Внизу — только сами кнопки разделов: закрытый лист
уезжает под экран целиком, а высоту дока оболочка меряет сама (`--dock-h`), так
что лист, лента и сообщения никогда не накрывают кнопки. Всё остальное — подэкраны
внутри раздела: у них есть кнопка «назад» (и аппаратная кнопка телефона), поэтому
рынок, верфь, контракты, склад и сканер больше не отнимают место в доке.

1. **Система** — хаб раздела: описание системы, планеты, станции и три входа —
   «Исследование», «Ресурсы» и «Станции». Здесь же карточка своей базы
   (`Строительство станции` / `Управление базой`) и список соседей для прыжка:
   видно топливо, время, риск и цену маршрута.
2. **Исследование** (`Система` → «Исследование») — полный скан системы,
   разведка поясов и дальний скан (пробивает туман за соседней системой). Сканер
   тратит топливо и работает над одной задачей за раз; прогресс и прерывание —
   там же. Пока пояс не нанесён на карты, добыча в нём запрещена.
3. **Ресурсы** (`Система` → «Ресурсы») — пояса текущей системы: состав, запас и
   выработанность. План вахты задаётся счётчиком (или «ДО ПОЛНОГО ТРЮМА»),
   работает фиксированными заходами бура по 12 секунд, останавливается в любой
   момент, а пояс постепенно истощается. Неизученный пояс ведёт в «Исследование».
4. **Груз** — трюм флагмана и две кнопки: «Рынок» и «Склад». Каждая строка
   показывает цену продажи здесь, вес партии и куда ресурс идёт дальше.
5. **Склады по станциям** — своя база (объём растёт с постройками) и
   арендованные ячейки на станциях фракций: у каждой станции свой ящик, поэтому
   груз нельзя «телепортировать» — забрать или продать его можно только там, где
   он лежит. Сводка «Другие ваши склады» показывает адреса и заполненность.
6. **Станции** (`Система` → «Станции») — меню станции: её услуги отдельными
   кнопками (рынок, контракты, верфь, склад) и доковые службы (заправка,
   ремонт). Верфь, рынок и контракты живут только здесь — своих вкладок у них
   больше нет. Если в системе станций нет, этот экран предлагает заложить свою.
7. **Закладка станции** (`Система` → «Строительство станции») — воронка: ничья
   система *под кораблём* → полный скан → планета с твёрдой корой → металл в трюме
   и закладка склада → материалы на склад → КЦ Mk1 (базовая станция). Удалённых
   закладок нет: участок выбирают только там, где стоит корабль и только в
   отсканированной системе, поэтому панель показывает планеты текущей системы.
   Профильный бонус планеты включается только после ввода базы в строй. Старые сейвы
   0.1.x читаются по постройкам: база, которая уже стояла со складом, больше не
   остаётся «участком» без ёмкости склада и без права на КЦ.
8. **Развитие** — после КЦ Mk1 открываются док, верфь, переработка, радар,
   лаборатория и офис флота; кредиты и материалы везут кораблём.
9. **Услуги и репутация** — рынок, верфь, ремонт, заправка, склад и доска
   контрактов есть только на станциях, которые вас обслуживают: с враждебной
   фракцией сервис закрыт, в безвластии работает чёрный рынок.
10. **Верфи и модули** — переоборудование доступно только там, где есть верфь: у
   фракций это узловые системы, а на своей базе можно построить собственную
   верфь и не зависеть от репутации. Каждая фракция ставит модули своей сборки
   (щиты Федерации, трюмы «Хеликса», движки Колоний, орудия Союза), и каждый
   модуль несёт клеймо верфи: сборки разных доков сочетаются на одном корпусе.
   Раздел `КОРАБЛЬ` показывает состояние и сборку флагмана, а `Верфь` — пять
   групп улучшений: ход и прыжок, защита и энергия, груз, сенсоры, вооружение.
11. **Флот, лента, настройки** — задания кораблей, сводка с подсказками «что
   дальше» (кнопки ведут сразу на нужный экран) и пауза, темп времени, обновления.
12. **Курьерские контракты** — на доске два вида работы: поставка в текущую
   систему и курьерский рейс в уже открытую систему. Курьеру фракция выдаёт
   *опечатанный* груз: продать, выгрузить или переработать его нельзя, а платят
   за число прыжков и расстояние до точки сдачи. Просроченный рейс забирает груз
   и репутацию, поэтому маршрут стоит считать заранее.

## Проверки

```bash
npm run verify         # типы, логика (smoke), серверный рендер панелей
npm run browser-check  # сборка в headless Chrome: старт игры, обход вкладок,
                       # вахта у пояса и закладка склада через интерфейс
```

## Android-приложение

```bash
npm run android:debug   # быстрый APK для телефона
npm run android:apk     # подписанный release-APK
```

Нужны JDK 17+ и Android SDK (platform 36, build-tools 36). Пути берутся из
`JAVA_HOME` и `ANDROID_HOME`, иначе — из обычных мест установки; адрес SDK
скрипт сам прописывает в `android/local.properties`. При необходимости можно
указать конкретный Gradle через `FRONTIER_GRADLE`, а быстрые Maven-зеркала —
через `FRONTIER_MAVEN_MIRROR=aliyun`. Подробности — в [android/README.md](android/README.md).

## Обновления из репозитория

Ни браузера, ни Play Store: приложение само спрашивает GitHub о последнем
релизе и ставит то, что там лежит.

* **Игра** — релиз содержит `frontier-web.zip` (собранные файлы игры). Оболочка
  скачивает его, распаковывает и меняет файлы на месте; сохранение не страдает,
  потому что адрес страницы не меняется и файлы живут на одном origin.
* **Оболочка** — в релизе лежит `frontier-<версия>.apk`. Он скачивается внутрь
  приложения и передаётся системному установщику: одно подтверждение, и
  FRONTIER перезапускается уже новой версией.

Проверка идёт тихо при запуске (не чаще раза в несколько часов) и вручную — из
раздела **НАСТРОЙКИ** (карточка **ОБНОВЛЕНИЕ**).

## Управление и настройки

* **Пауза** — кнопка `❚❚` в верхней панели (или `P` на клавиатуре): время,
  перелёты, добыча, стройка и флот останавливаются. Второе нажатие продолжает игру.
* **Раздел НАСТРОЙКИ** (клавиша `6`) — темп игрового времени (×0.5…×4),
  автосохранение и кнопка «сохранить сейчас», переключатели анимации прыжка,
  всплывающих сообщений и подтверждения прыжка, проверка обновлений и сводка по
  приложению. Настройки живут отдельно от сохранения: новая галактика их не сбрасывает.
* **Прыжок видно** — пока корабль между системами, в верхней панели появляется
  статус-бар с прогрессом, остатком времени и кнопкой «прервать», а на карте
  корабль идёт по линии маршрута. Анимацию можно выключить в настройках.
* **Клавиши** — `1`…`6` переключают шесть разделов, `P` — пауза, `Esc` — назад
  (подтверждение прыжка → подэкран → лист → выделение на карте).
* **Кнопка «назад» на телефоне** — аппаратная кнопка сначала снимает подтверждение
  прыжка, потом закрывает подэкран, потом лист, потом снимает выделение на карте;
  когда закрывать уже нечего, оболочка просит подтверждение и выходит по второму
  нажатию за две секунды. На Android 13 и новее система больше не зовёт
  `onBackPressed()`, поэтому оболочка регистрирует обработчик в системном
  диспетчере (`enableOnBackInvokedCallback` в манифесте) — кнопка ведёт себя
  одинаково на всех версиях.

## Релиз

```bash
npm run release -- patch          # 0.1.0 → 0.1.1: сборка, тег, релиз с двумя файлами
npm run release -- 0.4.0          # явная версия
npm run release -- patch --no-git # без коммита и пуша
```

Скрипт поднимает версию в `version.json` и `package.json`, собирает веб-бандл и
APK, коммитит и пушит, а затем создаёт релиз на GitHub с ассетами
`frontier-web.zip` и `frontier-<версия>.apk`. Токен берётся из `GH_TOKEN` /
`GITHUB_TOKEN` или из `~/.git-credentials`.
