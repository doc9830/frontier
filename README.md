# FRONTIER

Процедурная космическая песочница: торговля, добыча, своя станция и флот.
Игра — это веб-приложение (React + TypeScript + Vite) и одновременно
Android-приложение: тот же билд упаковывается в APK, где игра работает внутри
WebView и сама обновляется из этого репозитория.

## Что внутри

| Папка | Назначение |
| --- | --- |
| `src/` | игра: симуляция, панели интерфейса, сохранения в localStorage |
| `public/` | иконка, манифест PWA и офлайн-оболочка для браузера |
| `android/` | Android-оболочка: WebView, мост в игру и внутренний апдейтер |
| `scripts/` | сборка веб-бандла и публикация релизов |
| `version.json` | единственный источник версии: она попадает и в APK, и в веб-бандл |

## Игра в браузере

```bash
npm install
npm run dev        # разработка
npm run build      # dist/ — готовая игра
npm run verify     # типы, smoke-тесты, проверка рендера
```

## Игровой цикл

1. **Торговля и прыжки** — раздел `СИСТЕМА`: трассы, риски, покупка топлива.
2. **Разведка** — раздел `РАЗВЕДКА`: полный скан системы, разведка поясов и
   дальний скан (пробивает туман за соседней системой). Сканер тратит топливо и
   работает над одной задачей за раз; прогресс и прерывание — там же.
3. **Добыча** — раздел `СИСТЕМА`: у каждого пояса видно запас, состав и
   выработанность. План вахты задаётся счётчиком (или «ДО ПОЛНОГО ТРЮМА»),
   работает фиксированными заходами бура по 12 секунд, останавливается в любой
   момент, а пояс постепенно истощается.
4. **Закладка станции** — раздел `СТАНЦИЯ`, пока склад не поставлен, показывает
   воронку: ничья система → полный скан → планета с твёрдой корой → металл в
   трюме и закладка склада → материалы на склад → КЦ Mk1 (базовая станция).
   Профильный бонус планеты включается только после ввода базы в строй.
5. **Развитие** — после КЦ Mk1 открываются док, верфь, переработка, радар,
   лаборатория и офис флота; кредиты и материалы везут кораблём.
6. **Услуги и репутация** — рынок, верфь, ремонт, заправка и доска контрактов
   есть только на станциях, которые вас обслуживают: с враждебной фракцией
   сервис закрыт, в безвластии работает чёрный рынок.
7. **Верфи и модули** — переоборудование доступно только там, где есть верфь: у
   фракций это узловые системы, а на своей базе можно построить собственную
   верфь и не зависеть от репутации. Каждая фракция ставит модули своей сборки
   (щиты Федерации, трюмы «Хеликса», движки Колоний, орудия Союза), и каждый
   модуль несёт клеймо верфи: сборки разных доков сочетаются на одном корпусе.
   Раздел `КОРАБЛЬ` разбит на пять групп — ход и прыжок, защита и энергия, груз,
   сенсоры, вооружение: видно, что стоит, что требует верфь выше классом и каких
   материалов не хватает.
8. **Курьерские контракты** — на доске два вида работы: поставка в текущую
   систему и курьерский рейс в уже открытую систему. Курьеру фракция выдаёт
   *опечатанный* груз: продать, выгрузить или переработать его нельзя, а платят
   за число прыжков и расстояние до точки сдачи. Просроченный рейс забирает груз
   и репутацию, поэтому маршрут стоит считать заранее.

## Проверки

```bash
npm run verify         # типы, логика (smoke), серверный рендер панелей
npm run browser-check  # сборка в headless Chrome: старт игры, обход вкладок,
                       # вахта у пояса и закладка склада через интерфейс
```

## Android-приложение

```bash
npm run android:debug   # быстрый APK для телефона
npm run android:apk     # подписанный release-APK
```

Нужны JDK 17+ и Android SDK (platform 36, build-tools 36). Пути берутся из
`JAVA_HOME` и `ANDROID_HOME`, иначе — из обычных мест установки; адрес SDK
скрипт сам прописывает в `android/local.properties`. При необходимости можно
указать конкретный Gradle через `FRONTIER_GRADLE`, а быстрые Maven-зеркала —
через `FRONTIER_MAVEN_MIRROR=aliyun`. Подробности — в [android/README.md](android/README.md).

## Обновления из репозитория

Ни браузера, ни Play Store: приложение само спрашивает GitHub о последнем
релизе и ставит то, что там лежит.

* **Игра** — релиз содержит `frontier-web.zip` (собранные файлы игры). Оболочка
  скачивает его, распаковывает и меняет файлы на месте; сохранение не страдает,
  потому что адрес страницы не меняется и файлы живут на одном origin.
* **Оболочка** — в релизе лежит `frontier-<версия>.apk`. Он скачивается внутрь
  приложения и передаётся системному установщику: одно подтверждение, и
  FRONTIER перезапускается уже новой версией.

Проверка идёт тихо при запуске (не чаще раза в несколько часов) и вручную — из
раздела **НАСТРОЙКИ** (карточка **ОБНОВЛЕНИЕ**).

## Управление и настройки

* **Пауза** — кнопка `❚❚` в верхней панели (или `P` на клавиатуре): время,
  перелёты, добыча, стройка и флот останавливаются. Второе нажатие продолжает игру.
* **Раздел НАСТРОЙКИ** (клавиша `9`) — темп игрового времени (×0.5…×4),
  автосохранение и кнопка «сохранить сейчас», переключатели анимации прыжка,
  всплывающих сообщений и подтверждения прыжка, проверка обновлений и сводка по
  приложению. Настройки живут отдельно от сохранения: новая галактика их не сбрасывает.
* **Прыжок видно** — пока корабль между системами, в верхней панели появляется
  статус-бар с прогрессом, остатком времени и кнопкой «прервать», а на карте
  корабль идёт по линии маршрута. Анимацию можно выключить в настройках.
* **Клавиши** — `1`…`9` и `0` переключают все десять разделов, `P` — пауза,
  `Esc` — закрыть лист или снять выбор.

## Релиз

```bash
npm run release -- patch          # 0.1.0 → 0.1.1: сборка, тег, релиз с двумя файлами
npm run release -- 0.4.0          # явная версия
npm run release -- patch --no-git # без коммита и пуша
```

Скрипт поднимает версию в `version.json` и `package.json`, собирает веб-бандл и
APK, коммитит и пушит, а затем создаёт релиз на GitHub с ассетами
`frontier-web.zip` и `frontier-<версия>.apk`. Токен берётся из `GH_TOKEN` /
`GITHUB_TOKEN` или из `~/.git-credentials`.
